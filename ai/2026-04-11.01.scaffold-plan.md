## Steps

### 1. Root-level files

- `.gitignore` — covers `node_modules`, `.env*`, `dist/`, `.next/`, `cdk.out/`
- `docker-compose.yml` — local Postgres on port 5432 with shared database `vietthan`
- `README.md` — brief project description + local dev quickstart

### 2. `data/activities.json`

Port the 400 activity objects from `nyc-adventure/index.html` into a JSON array. Each entry:

```json
{
  "id": 1,
  "title": "Metrograph on the Lower East Side",
  "category": "cinema",
  "season": "any",
  "notes": "...",
  "tip": "..."
}
```

This is the canonical baseline dataset. It exists so the original activity list is reviewable in the repo and can be imported into a fresh database without depending on a production dump.

### 3. `apps/web/` — Next.js app skeleton

- `package.json` — dependencies: `next`, `react`, `react-dom`, `pg`, `zod`, `next-auth`; devDependencies: `typescript`, `@types/node`, `@types/react`, `@types/react-dom`, `tailwindcss`
- `src/app/` — App Router pages plus route handlers for server endpoints
- `src/app/api/auth/[...nextauth]/route.ts` — Auth.js handler stub
- `src/app/api/activities/route.ts` — placeholder route handler for activity listing and creation
- `src/app/api/activities/[id]/route.ts` — placeholder route handler for single-activity reads/updates/deletes
- `src/app/api/activities/[id]/complete/route.ts` — placeholder route handler for mark done / unmark
- `src/app/api/activities/pick/route.ts` — placeholder route handler for surprise picker
- `src/app/api/me/route.ts` — placeholder route handler for current user profile
- `src/db/client.ts` — `pg.Pool` setup reading `DATABASE_URL` from env and setting `search_path` to `our_adventures`
- `src/db/queries/` — empty directory for query functions against the shared repo-level schema
- `src/lib/auth.ts` — Auth.js config stub (Google provider, allowlist, JWT strategy)

### 4. `db/` — database contract

- `migrations/001_initial_schema.sql` — creates schema `our_adventures`, defines the canonical category type, and creates the full table/index set inside it
- `README.md` — notes on how to initialize a fresh DB from migrations plus the baseline activity dataset

Bootstrap `apps/web` with `create-next-app`:
```bash
npx create-next-app@latest web \
  --typescript \
  --tailwind \
  --app \
  --src-dir \
  --no-import-alias
```

Then add:
- `next.config.ts` — no `output: 'export'` (server mode)
- `src/types/` — empty directory
- `src/components/` — empty directory

### 5. `infra/` — CDK skeleton

- `package.json` — dependencies: `aws-cdk-lib`, `constructs`; devDependencies: `typescript`, `ts-node`, `aws-cdk`
- `tsconfig.json` — standard CDK tsconfig
- `cdk.json` — `{ "app": "npx ts-node bin/app.ts" }`
- `bin/app.ts` — CDK app entry, instantiates all three stacks
- `lib/network-stack.ts` — stub (VPC, subnets, security groups)
- `lib/database-stack.ts` — stub (RDS PostgreSQL t4g.micro)
- `lib/compute-stack.ts` — stub (EC2 t4g.nano, IAM profile, nginx + Next.js systemd service)

### 6. `.github/workflows/`

- `deploy-app.yml` — stub with correct triggers and steps outlined for building the Next.js app, running migrations, and restarting the web service
- `deploy-infra.yml` — stub for manual `cdk deploy`

---

## What this is NOT

- No real route logic — routes are stubs only
- No CDK resources deployed — stacks are scaffolded but not deployed
- No Auth.js fully configured — needs `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_SECRET`
- No GHA secrets set up — workflows are stubs
- No persistent seed script yet — choose a simple import path later if loading `data/activities.json` should be automated

All of that comes in subsequent phases. This scaffold just ensures `npm install` works in each package and the directory contract is established.
