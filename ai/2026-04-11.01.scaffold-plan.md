## Steps

### 1. Root-level files ✅

- `.gitignore` — covers `node_modules`, `.env*`, `dist/`, `.next/`, `cdk.out/`
- `docker-compose.yml` — local Postgres on port 5432 with database `vietthan`; mounts `001_initial_schema.sql` as an initdb script so the schema initializes automatically on first run
- `README.md`, `AGENTS.md`, `CLAUDE.md`

### 2. `data/activities.json` ✅

400 activity objects ported from `nyc-adventure/index.html`. Includes a `link` field (not in original plan) for activities that have an associated URL. Shape:

```json
{
  "id": 1,
  "title": "...",
  "category": "cinema",
  "season": "any",
  "notes": "...",
  "tip": "...",
  "link": "https://..."
}
```

### 3. `apps/web/` — Next.js app skeleton ✅

Created via `create-next-app` (Next.js 16, React 19, TypeScript, Tailwind v4, App Router, src-dir). Notable implementation details:

- **`next-auth` v4** (not v5) — `authOptions` pattern, `NextAuthOptions` type
- **`ALLOWED_EMAILS` env var** — comma-separated allowlist read at startup; if empty, all Google accounts allowed (useful for local dev)
- **`db/client.ts`** — singleton `pg.Pool` with Next.js hot-reload guard; `withSchemaSearchPath()` helper that checks out a client, sets `search_path = our_adventures, public`, runs a callback, and releases
- **`src/types/activity.ts`** — `Activity`, `ActivityCategory`, `ActivitySeason` types (matches DB schema exactly, includes `link` field)
- All route stubs return placeholder JSON; none touch the database yet

Remaining: `src/components/` directory (empty, needed as a home for shared UI components)

### 4. `db/` — database contract ✅

- `migrations/001_initial_schema.sql` — idempotent (`IF NOT EXISTS` throughout); creates `our_adventures` schema, `activity_category` enum, `activities` / `users` / `completions` tables, and two indexes
- `db/README.md`

### 5. `infra/` — CDK skeleton ⬜

VPC, RDS, and shared security controls live in `shared-aws-infra` (already deployed). This CDK project owns only the compute layer.

- `package.json` — dependencies: `aws-cdk-lib`, `constructs`; devDependencies: `typescript`, `ts-node`, `aws-cdk`
- `tsconfig.json` — standard CDK tsconfig
- `cdk.json` — `{ "app": "npx ts-node bin/app.ts" }`
- `bin/app.ts` — CDK app entry, instantiates `ComputeStack` only
- `lib/compute-stack.ts` — EC2 t4g.nano in public subnet; reads `/shared/network/vpc-id`, `/shared/network/app-tier-sg-id`, `/shared/db/endpoint` from SSM at deploy time; `GitHubActions-OurAdventures` IAM role (OIDC, scoped to `repo:VietThan/our-adventures:ref:refs/heads/main`, references `/shared/iam/github-oidc-provider-arn`)

### 6. `.github/workflows/` ⬜

- `deploy-app.yml` — triggers on push to `main`; steps: build Next.js, rsync to EC2, run migrations, restart web systemd service via SSH
- `deploy-infra.yml` — manual trigger only; runs `cdk deploy`

## What this is NOT

- No real route logic — routes are stubs only
- No CDK resources deployed — stacks are scaffolded but not deployed
- No Auth.js fully configured — needs `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_SECRET`
- No GHA secrets set up — workflows are stubs
- No persistent seed script yet — choose a simple import path later if loading `data/activities.json` should be automated

All of that comes in subsequent phases. This scaffold just ensures `npm install` works in each package and the directory contract is established.
