# Plan: Deploy app reads EC2 host from SSM

**Date:** 2026-04-25
**Status:** Not started
**Depends on:** RDS TLS + deploy automation rollout complete

---

## Goal

Remove the manual GitHub Actions variable update:

```bash
gh variable set EC2_HOST \
  --repo VietThan/our-adventures \
  --body "<new-instance-ip>"
```

After this change, `deploy-app.yml` should read the current EC2 public IP from
SSM parameter `/our-adventures/ec2/public-ip` at workflow runtime and use that
value for `ssh-keyscan`, `rsync`, and `ssh`.

## Proposed implementation

### Step 1: Add SSM read permission to the GitHub Actions role

Repository: `shared-aws-infra`

Update `shared-aws-infra/lib/security-stack.ts` so
`GitHubActions-OurAdventures` can read only the app EC2 public IP parameter:

```ts
ourAdventuresRole.addToPolicy(
  new iam.PolicyStatement({
    effect: iam.Effect.ALLOW,
    actions: ['ssm:GetParameter'],
    resources: [
      `arn:aws:ssm:${this.region}:${this.account}:parameter/our-adventures/ec2/public-ip`,
    ],
  }),
);
```

Keep this permission narrow. Do not grant `/our-adventures/*`, because that path
also contains application secrets read by the EC2 instance profile.

Deploy shared infra after the change:

```bash
cd /Users/vietthan/projects/workspace-viett/shared-aws-infra
npm run test
npm run cdk -- deploy SecurityStack --profile VietThan-Admin-SSO
```

If the actual stack name is not `SecurityStack`, run `npm run cdk -- ls` and use
the listed security stack name.

### Step 2: Add OIDC AWS credentials to `deploy-app.yml`

Repository: `our-adventures`

Add workflow permissions near the top, matching `deploy-infra.yml`:

```yaml
permissions:
  id-token: write
  contents: read
```

Add AWS credentials setup before SSH setup:

```yaml
- name: Configure AWS credentials (OIDC)
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: ${{ vars.AWS_DEPLOY_ROLE_ARN }}
    aws-region: us-east-1
```

Add a step that reads the EC2 host from SSM:

```yaml
- name: Read EC2 host from SSM
  id: ec2
  run: |
    EC2_HOST=$(aws ssm get-parameter \
      --name /our-adventures/ec2/public-ip \
      --query 'Parameter.Value' \
      --output text)
    echo "host=$EC2_HOST" >> "$GITHUB_OUTPUT"
```

### Step 3: Replace `vars.EC2_HOST` references

Replace every `${{ vars.EC2_HOST }}` in `.github/workflows/deploy-app.yml` with:

```yaml
${{ steps.ec2.outputs.host }}
```

Affected commands:

- `ssh-keyscan`
- four `rsync` targets
- the final `ssh ... 'bash -s'` command

### Step 4: Update docs

Update docs that currently describe manual `EC2_HOST` handling:

- `ai/2026-04-24.00.phase0-completion-log.md`
  - Change `/our-adventures/ec2/public-ip` from "operator (set EC2_HOST
    variable)" to "deploy-app.yml via GitHub OIDC".
  - Mark `EC2_HOST` as legacy or remove it from required setup.
- `ai/2026-04-25.00.rds-tls-and-deploy-automation.md`
  - Move "remove the manual EC2_HOST GitHub Actions variable update" from
    remaining follow-up to completed once implemented.
  - Update rollout commands so replacement no longer requires
    `gh variable set EC2_HOST`.

### Step 5: Verification

Before removing the `EC2_HOST` repo variable, run the workflow with the new SSM
lookup in place:

```bash
gh workflow run deploy-app.yml --repo VietThan/our-adventures
gh run list --repo VietThan/our-adventures --workflow "Deploy app" --limit 1
```

Success criteria:

- Workflow reaches the `Read EC2 host from SSM` step and prints no AWS
  authorization error.
- `ssh-keyscan`, `rsync`, and `ssh` use the host read from SSM.
- Workflow completes successfully.
- `https://adventures.sleepyshortcake.com` returns HTTP 200 after the deploy.

After the workflow succeeds, remove the now-unused repo variable:

```bash
gh variable delete EC2_HOST --repo VietThan/our-adventures
```

## Risks and mitigations

### Risk: OIDC role lacks SSM permission

Confirmed current state: `GitHubActions-OurAdventures` only has `sts:AssumeRole`
on CDK bootstrap roles. Mitigation: deploy the shared infra IAM change before
changing `deploy-app.yml`.

### Risk: empty or stale SSM public IP

`/our-adventures/ec2/public-ip` is written by `ComputeStack`, but the plan does
not verify whether every EC2 stop/start updates the SSM parameter. Mitigation:
keep the Cloudflare DNS update in `deploy-app.yml`, and during verification
confirm the SSM value matches the running EC2 public IP.

### Risk: GitHub output injection or malformed IP

The SSM value should be an IPv4 address, but the workflow can cheaply validate it
before using it:

```bash
case "$EC2_HOST" in
  *[!0-9.]*|'') echo "Invalid EC2_HOST from SSM: $EC2_HOST" >&2; exit 1 ;;
esac
```

This validation is optional but recommended.
