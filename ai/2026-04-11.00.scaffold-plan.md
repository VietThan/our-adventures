## Steps

### 1. Root-level files

- `.gitignore` — covers `node_modules`, `.env*`, `dist/`, `.next/`, `cdk.out/`
- `docker-compose.yml` — local Postgres on port 5432
- `README.md` — brief project description + local dev quickstart

### 2. `data/activities.json`

Port the ~195 activity objects from `nyc-adventure/index.html` into a JSON array. Each entry:

```json
{
  "id": 1,
  "title": "Metrograph on the Lower East Side",
  "category": "cinema",
  "season": "any",
  "notes": "...",
  "tip": "..."
}
```

This is the canonical seed source. The API's `scripts/seed.ts` reads this file and inserts into the DB.

### 3. `apps/api/` — Fastify skeleton

- `package.json` — dependencies: `fastify`, `pg`, `node-pg-migrate`, `@fastify/cookie`, `zod`; devDependencies: `typescript`, `tsx`, `@types/node`, `@types/pg`
- `tsconfig.json` — `target: ES2022`, `module: NodeNext`, `strict: true`, `outDir: dist`
- `src/server.ts` — Fastify instance, registers routes, listens on port `3001`
- `src/routes/` — empty placeholder files: `activities.ts`, `completions.ts`, `me.ts`
- `src/db/client.ts` — `pg.Pool` setup reading `DATABASE_URL` from env
- `src/db/queries/` — empty directory
- `src/auth.ts` — placeholder for Auth.js JWT verification middleware
- `migrations/001_initial_schema.sql` — full schema (activities, users, completions, indexes)
- `scripts/seed.ts` — reads `../../../data/activities.json`, inserts into activities table

### 4. `apps/web/` — Next.js skeleton

Bootstrap with `create-next-app`:
```bash
npx create-next-app@latest web \
  --typescript \
  --tailwind \
  --app \
  --src-dir \
  --no-import-alias
```

Then add:
- `next.config.ts` — no `output: 'export'` (server mode)
- `src/app/api/auth/[...nextauth]/route.ts` — Auth.js handler stub
- `src/lib/auth.ts` — Auth.js config stub (Google provider, allowlist, JWT strategy)
- `src/lib/api.ts` — empty typed API client
- `src/types/` — empty directory
- `src/components/` — empty directory

### 5. `infra/` — CDK skeleton

- `package.json` — dependencies: `aws-cdk-lib`, `constructs`; devDependencies: `typescript`, `ts-node`, `aws-cdk`
- `tsconfig.json` — standard CDK tsconfig
- `cdk.json` — `{ "app": "npx ts-node bin/app.ts" }`
- `bin/app.ts` — CDK app entry, instantiates all three stacks
- `lib/network-stack.ts` — stub (VPC, subnets, security groups)
- `lib/database-stack.ts` — stub (RDS PostgreSQL t4g.micro)
- `lib/compute-stack.ts` — stub (EC2 t4g.nano, IAM profile)

### 6. `.github/workflows/`

- `deploy-app.yml` — stub with correct triggers and steps outlined but not yet wired (SSH key not set up yet)
- `deploy-infra.yml` — stub for manual `cdk deploy`

---

## What this is NOT

- No real route logic — routes are stubs only
- No CDK resources deployed — stacks are scaffolded but not deployed
- No Auth.js fully configured — needs `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `AUTH_SECRET`
- No GHA secrets set up — workflows are stubs

All of that comes in subsequent phases. This scaffold just ensures `npm install` works in each package and the directory contract is established.

- [ ] `cd apps/api && npm install` succeeds
- [ ] `cd apps/web && npm install && npm run dev` serves the Next.js default page
- [ ] `cd infra && npm install && npx cdk ls` lists the three stacks without error
- [ ] `docker compose up` starts Postgres on port 5432
- [ ] Everything committed and pushed to `main` on `VietThan/our-adventures`
