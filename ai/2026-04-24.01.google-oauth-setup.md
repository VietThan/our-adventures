# Google OAuth Setup

One-time setup to get `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` for Auth.js.

---

## 1. Create a Google Cloud project (if you don't have one)

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Click the project dropdown → **New Project**
3. Name it `our-adventures` → **Create**

---

## 2. Configure the OAuth consent screen

1. In the left sidebar: **APIs & Services** → **OAuth consent screen**
2. User type: **External** → **Create**
3. Fill in:
   - App name: `Our Adventures`
   - User support email: your Gmail
   - Developer contact email: your Gmail
4. **Save and continue** through to the end

Then go to **Audience** → **Add users** → add both `viet@...` and `linh@...` emails.

---

## 3. Create OAuth credentials

1. **APIs & Services** → **Credentials** → **Create Credentials** → **OAuth client ID**
2. Application type: **Web application**
3. Name: `our-adventures`
4. **Authorized JavaScript origins**: `https://adventures.sleepyshortcake.com`
5. **Authorized redirect URIs**: `https://adventures.sleepyshortcake.com/api/auth/callback/google`
6. **Create**

Copy the **Client ID** and **Client Secret**.

---

## 4. Store in SSM

```bash
aws ssm put-parameter --name /our-adventures/auth/google-client-id --value "<Client ID>" --type SecureString

aws ssm put-parameter --name /our-adventures/auth/google-client-secret --value "<Client Secret>" --type SecureString
```

---

## Notes

- The app is in **External** mode but only the two test users can log in — Auth.js enforces an email allowlist in the `signIn` callback.
- To go to production later: **OAuth consent screen** → **Publish App**. Not needed while both users are listed as test users.
- If the EC2 IP changes (instance stop/start), update the A record in Cloudflare — the OAuth redirect URIs use the domain, not the IP, so no Google Console changes needed.
