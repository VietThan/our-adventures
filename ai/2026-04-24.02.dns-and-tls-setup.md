# DNS and TLS Setup

One-time setup to point `adventures.sleepyshortcake.com` at the EC2 instance and provision a TLS certificate.

Uses **DNS-01 challenge** (not HTTP-01) so the Cloudflare proxy (orange cloud) can stay enabled. Cloudflare handles TLS between the browser and Cloudflare; Let's Encrypt handles TLS between Cloudflare and EC2 (required for **Full (strict)** mode).

---

## 1. Get the EC2 public IP

```bash
aws ssm get-parameter --name /our-adventures/ec2/public-ip --query 'Parameter.Value' --output text
```

---

## 2. Add DNS A record in Cloudflare

1. Go to Cloudflare dashboard → `sleepyshortcake.com` → **DNS**
2. Add a record:
   - Type: `A`
   - Name: `adventures`
   - IPv4 address: the IP from step 1
   - Proxy status: **Proxied** (orange cloud)
3. Save

Verify (proxied — will return Cloudflare IPs, not EC2 IP):

```bash
dig adventures.sleepyshortcake.com +short
```

---

## 3. Set Cloudflare SSL/TLS mode to Full (strict)

1. Cloudflare dashboard → `sleepyshortcake.com` → **SSL/TLS** → **Configure**
2. Select **Full (strict)**
3. Save

This is required — **Flexible** mode causes an infinite redirect loop because nginx also redirects HTTP→HTTPS.

---

## 4. Create a Cloudflare API token

Required for DNS-01 challenge (certbot adds a TXT record to prove domain ownership).

1. Go to [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) → **Create Token**
2. Use the **Edit zone DNS** template
3. Set:
   - Token name: `our-adventures Edit zone DNS`
   - Permissions: `Zone` / `DNS` / **Edit**
   - Zone Resources: `Include` / `Specific zone` / `sleepyshortcake.com`
4. **Continue to summary** → **Create Token** — copy it, you won't see it again

---

## 5. Open a shell on the EC2 instance

The `deploy` user's sudo is scoped only to `systemctl restart web` — use SSM Session Manager with the admin profile instead, which gives full sudo as `ssm-user`:

```bash
INSTANCE_ID=$(aws ec2 describe-instances \
  --filters "Name=tag:aws:cloudformation:stack-name,Values=ComputeStack" "Name=instance-state-name,Values=running" \
  --query 'Reservations[0].Instances[0].InstanceId' --output text \
  --profile VietThan-Admin-SSO)

aws ssm start-session --target $INSTANCE_ID --profile VietThan-Admin-SSO
```

Requires the [Session Manager plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/install-plugin-macos-overview.html). For macOS arm64:

```bash
curl "https://s3.amazonaws.com/session-manager-downloads/plugin/latest/mac_arm64/session-manager-plugin.pkg" -o "session-manager-plugin.pkg"
sudo installer -pkg session-manager-plugin.pkg -target /
sudo ln -s /usr/local/sessionmanagerplugin/bin/session-manager-plugin /usr/local/bin/session-manager-plugin
```

---

## 6. Provision TLS certificate with Certbot (DNS-01)

Inside the session, switch to root:

```bash
sudo su
```

Then:

```bash
# Install Certbot and the Cloudflare DNS plugin.
# python3-certbot-dns-cloudflare is not in the AL2023 repo.
# Use a virtualenv to avoid conflicts with system-managed Python packages (josepy etc.).
dnf install -y python3-pip
python3 -m venv /opt/certbot
/opt/certbot/bin/pip install certbot certbot-dns-cloudflare certbot-nginx
ln -sf /opt/certbot/bin/certbot /usr/bin/certbot

# Store the Cloudflare API token
mkdir -p /etc/letsencrypt
tee /etc/letsencrypt/cloudflare.ini > /dev/null << 'EOF'
dns_cloudflare_api_token = <your-api-token>
EOF
chmod 600 /etc/letsencrypt/cloudflare.ini

# Provision the certificate (will prompt for email)
certbot certonly \
  --dns-cloudflare \
  --dns-cloudflare-credentials /etc/letsencrypt/cloudflare.ini \
  -d adventures.sleepyshortcake.com

# Install into nginx
certbot install --nginx -d adventures.sleepyshortcake.com
```

Test automatic renewal:

```bash
certbot renew --dry-run
```

Verify end-to-end:

```bash
curl -sL -o /dev/null -w "%{http_code}" https://adventures.sleepyshortcake.com
# expect 200
```

---

## Notes

- **IP changes on stop/start.** If the EC2 instance is ever stopped and restarted, it gets a new public IP. Update the Cloudflare A record and rerun Certbot.
- **Certbot auto-renews** via a systemd timer installed automatically — no manual renewal needed under normal operation.
- **Cloudflare token is stored on the instance** at `/etc/letsencrypt/cloudflare.ini` (chmod 600, root only). It is not in SSM or source control.
- **Do not use Flexible SSL mode in Cloudflare.** It causes an infinite redirect loop (Cloudflare sends HTTP to EC2, nginx redirects to HTTPS, repeat). Always use **Full (strict)**.
