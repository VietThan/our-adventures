# DNS and TLS Setup

One-time setup to point `adventures.sleepyshortcake.com` at the EC2 instance and provision a TLS certificate.

---

## 1. Get the EC2 public IP

```bash
aws ssm get-parameter --name /our-adventures/ec2/public-ip --query 'Parameter.Value' --output text
```

---

## 2. Add DNS A record in Cloudflare

1. Go to Cloudflare dashboard → `sleepyshortcake.com` → **DNS**
2. Add a record:
   - Type: `A`
   - Name: `adventures`
   - IPv4 address: the IP from step 1
   - Proxy status: **DNS only** (grey cloud, not proxied) — required for Certbot HTTP-01 challenge and direct SSH access
3. Save

Wait a minute for DNS to propagate, then verify:

```bash
dig adventures.sleepyshortcake.com +short
```

---

## 3. Provision TLS certificate with Certbot

SSH into the EC2 instance:

```bash
ssh deploy@adventures.sleepyshortcake.com
```

Install Certbot and provision the certificate:

```bash
sudo dnf install -y certbot python3-certbot-nginx
sudo certbot --nginx -d adventures.sleepyshortcake.com
```

Certbot will:
- Verify domain ownership via HTTP-01 challenge (requires port 80 open and DNS pointing at the instance)
- Issue a certificate from Let's Encrypt
- Automatically update the nginx config to add the HTTPS server block and redirect HTTP → HTTPS

Test automatic renewal:

```bash
sudo certbot renew --dry-run
```

---

## Notes

- **IP changes on stop/start.** If the EC2 instance is ever stopped and restarted, it gets a new public IP. Update the Cloudflare A record and rerun Certbot.
- **Certbot auto-renews** via a systemd timer installed automatically — no manual renewal needed under normal operation.
- **Proxy status must stay grey (DNS only).** If Cloudflare proxying is enabled, the HTTP-01 challenge will fail because Cloudflare intercepts the request.
